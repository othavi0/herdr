O Herdr funciona sem arquivo de configuração. Adicione um quando quiser teclas personalizadas, temas, layouts da barra lateral, notificações ou comportamento avançado.

A [Referência de configuração](/pt-br/docs/config-reference/) lista todas as configurações e atalhos, com tipos, padrões e valores aceitos. Esta página cobre a configuração inicial, receitas comuns e estruturas de configuração que precisam de mais explicação do que uma linha da referência.

## Arquivo de configuração

O Herdr lê a configuração de:

```text
Linux and macOS: ~/.config/herdr/config.toml
Windows:          %APPDATA%\herdr\config.toml
```

Execute `herdr --help` para ver o caminho de configuração resolvido no seu sistema.

Imprima a configuração padrão completa:

```bash
herdr --default-config
```

Salve essa saída como sua configuração se quiser um ponto de partida completo:

```bash
herdr --default-config > ~/.config/herdr/config.toml
```

Se um valor de configuração for inválido, o Herdr volta para um padrão seguro e mostra um aviso na inicialização.

O Herdr mostra a configuração da primeira execução quando `onboarding` está ausente ou é true. Continuar a partir do onboarding grava `onboarding = false` e abre as configurações na aba de integrações. Defina `onboarding = false` para pular esse fluxo depois da configuração inicial.

```toml
onboarding = false
```

## Recarregar a configuração

Recarregue um servidor em execução depois de editar `config.toml`:

```bash
herdr server reload-config
```

Você também pode abrir o menu global no Herdr e escolher `reload config`.

O recarregamento aplica a maioria das configurações de interface sem reiniciar os painéis. Configurações lidas só na inicialização ainda exigem reinício.

Temas, layouts da barra lateral, comportamento de cópia e outras configurações de apresentação vêm da configuração local do cliente, inclusive ao visualizar uma máquina por SSH. Padrões de painel, worktrees, integrações e comandos personalizados pertencem ao servidor onde os painéis rodam. A ação `reload config` da interface recarrega as configurações locais do cliente e a configuração do servidor selecionado. Os atalhos locais também recarregam. Com `--remote-keybindings server`, o Herdr usa os atalhos do servidor selecionado.

## Tamanho do terminal headless

Quando nenhum cliente está anexado, o servidor usa um terminal virtual de 120×40 para o layout e para os painéis novos. Para orquestração headless, mude esse valor de reserva com:

```toml
[server]
headless_cols = 160
headless_rows = 50
```

Com um cliente anexado, todas as abas seguem o tamanho dele. Com vários clientes, cada aba visualizada segue o cliente que a focou, selecionou ou interagiu com ela por último. Quando todos os clientes menos um se desanexam (detach), todas as abas voltam na hora ao tamanho do cliente restante. Quando não resta nenhum cliente, os PTYs dos painéis existentes mantêm o último tamanho e o novo layout headless usa o valor de reserva configurado.

## Padrões do terminal

Defina o executável que o Herdr usa para novos painéis interativos:

```toml
[terminal]
default_shell = "nu"
```

Quando o valor não está definido ou está vazio, o Herdr usa `$SHELL` e depois `/bin/sh` no Unix. No Windows, ele usa `pwsh.exe` (PowerShell 7) quando esse nome é resolvido no `PATH` e, caso contrário, o `powershell.exe` que vem com o sistema (Windows PowerShell 5.1). O valor é um nome ou caminho de executável, não uma linha de comando do shell. Os painéis existentes mantêm o shell atual até serem recriados. No Unix, as strings de atalhos de comandos personalizados rodam por `/bin/sh -c` nos comandos de painel e por `/bin/sh -lc` nos comandos desanexados. No Windows, elas rodam por `cmd.exe /d /c`.

Defina como o Herdr inicia os shells dos novos painéis interativos:

```toml
[terminal]
shell_mode = "auto"
```

`shell_mode = "auto"` inicia login shells no macOS, para que a configuração de PATH feita só no login, como `/usr/libexec/path_helper` e a inicialização do shell do Homebrew, rode nos novos painéis. Nas outras plataformas, ele mantém o comportamento atual de shell sem login. Use `"login"` para forçar a inicialização como login shell ou `"non_login"` para forçar a inicialização sem login. Painéis de comando, atalhos de comandos personalizados desanexados e execuções com argv explícito mantêm seus caminhos atuais de execução.

Defina a política de diretório de trabalho para novos painéis, abas e workspaces:

```toml
[terminal]
new_cwd = "follow"
```

`new_cwd = "follow"` mantém o comportamento padrão e herda o diretório do painel ou workspace de origem. Quando não há workspace de origem, o Herdr começa em `$HOME`. Use `"home"` para sempre começar em `$HOME`, `"current"` para usar o diretório do processo do Herdr ou um caminho fixo como `"~/Projects"`. Valores explícitos de `--cwd` vindos da CLI ou da API do socket continuam tendo precedência.

## Worktrees

Defina o diretório raiz que o Herdr usa para os checkouts de worktrees do Git criados pela barra lateral:

```toml
[worktrees]
directory = "~/.herdr/worktrees"
```

O Herdr cria os checkouts em `<directory>/<repo>/<branch-slug>`. Para checkouts lado a lado com o repositório, defina um diretório como `~/Projects/herdr-worktrees`. O app resolve valores relativos para um caminho absoluto quando aplica a configuração.

As ações de worktree ficam nas linhas de workspaces do Git. `New worktree` cria um checkout. Se a branch digitada já existe localmente, o Herdr faz checkout dela. Caso contrário, cria a branch. Em seguida, abre o checkout como um novo workspace do Herdr e o agrupa sob o workspace de origem. `Open worktree...` lista os checkouts de worktrees do Git que já existem para aquele repositório. Escolher um checkout já aberto foca nele, e escolher um checkout fechado o abre no mesmo grupo.

Worktrees agrupados continuam se comportando como workspaces normais do Herdr. Você pode focar, renomear e fechar cada um, e cada um tem suas próprias abas e painéis. A linha pai é o workspace original. Fechar a linha pai fecha o grupo inteiro no Herdr, mas não apaga as pastas de checkout nem as branches.

Para apagar um checkout de worktree, use `Delete worktree checkout...` em um workspace filho do grupo. O Herdr executa `git worktree remove` e primeiro pede ao Git uma remoção segura. Se o Git recusar porque o checkout tem arquivos modificados ou não rastreados, o Herdr pergunta de novo antes de executar a remoção forçada. O Herdr não apaga branches.

## Anexação remota

Por padrão, a anexação remota gerencia a conexão SSH com keepalives temporários e, onde houver suporte, reutiliza a conexão.

```toml
[remote]
manage_ssh_config = true
```

Com essa opção ativa, `herdr --remote` grava uma configuração SSH temporária e privada que inclui primeiro as suas configurações SSH de usuário e do sistema e depois acrescenta valores de reserva para `ServerAliveInterval` e `ServerAliveCountMax`. As suas próprias configurações de keepalive têm precedência. Clientes Linux e macOS também usam um socket de controle privado do OpenSSH por anexação, para reutilizar a primeira conexão autenticada. O OpenSSH do Windows não faz isso. Defina `manage_ssh_config = false` para fazer a anexação remota pelo `ssh` puro, sem a configuração gerada pelo Herdr nem o socket de controle.

## Atalhos de teclado

Para uma introdução guiada ao prefixo e uma configuração sem prefixo já testada, veja [Teclado](/pt-br/docs/keyboard/).

O Herdr tem um modo de prefixo parecido com o do tmux. O prefixo padrão é `ctrl+b`. As strings de atalho são explícitas. `prefix+n` significa pressionar o prefixo configurado e depois `n`. `ctrl+alt+n` é um atalho direto no modo terminal.

Uma pequena substituição de atalhos fica assim:

```toml
[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"
```

`keys.prefix` também aceita um array quando você precisa entrar no modo de prefixo por mais de uma tecla, por exemplo para compartilhar uma configuração entre o macOS e uma máquina Linux remota:

```toml
[keys]
prefix = ["ctrl+space", "ctrl+s"]
```

Todo prefixo configurado entra no mesmo modo de prefixo e dispara todas as ações `prefix+...`. A primeira entrada é o prefixo principal mostrado na barra de status. O painel de ajuda do app, em `prefix+?`, lista todos eles.

O mapa de teclas padrão usa o prefixo primeiro, para que o Herdr não roube a entrada de shells, editores, tmux ou apps de terminal. Procure `keys.` na [Referência de configuração](/pt-br/docs/config-reference/) para ver todas as ações e os atalhos padrão. O painel de ajuda do app, em `prefix+?`, mostra os atalhos ativos.

Um atalho também pode ser um array quando uma ação precisa de vários atalhos:

```toml
[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]
```

As ações opcionais ficam sem atalho por padrão. Associe-as com `prefix+` para o comportamento no modo de prefixo, ou use uma combinação explícita com modificador quando quiser de propósito um atalho direto. Por exemplo, redimensionar painéis com um só toque, no estilo do tmux, sem entrar no modo de redimensionamento:

```toml
[keys]
resize_pane_left = "ctrl+shift+alt+left"
resize_pane_down = "ctrl+shift+alt+down"
resize_pane_up = "ctrl+shift+alt+up"
resize_pane_right = "ctrl+shift+alt+right"
```

As strings de tecla aceitam teclas simples, combinações com modificadores como `ctrl+a`, `shift+n`, `alt+1` e `cmd+k`, e teclas especiais como `enter`, `tab`, `esc`, `left`, `right`, `up` e `down`. Nomes de pontuação como `minus`, `comma`, `ampersand`, `plus` e `backtick` também são aceitos. Teclas imprimíveis simples usadas como atalho direto, como `n`, não são seguras porque interceptam a digitação. Use `prefix+n`, a menos que você queira de propósito um atalho direto. Os campos `navigate_workspace_*` e `navigate_pane_*` valem só no modo Navigate e podem usar teclas simples como `j` ou `k`. Eles não podem usar `prefix+`, `esc`, `enter`, `tab`, `shift+tab`, `left`, `right` nem `1` a `9` sem modificador. As setas para a esquerda e para a direita são aliases permanentes da navegação para o painel à esquerda e à direita. Esses atalhos do modo Navigate são independentes dos atalhos de ações gerais, como `focus_pane_down = "prefix+j"`. Quando os dois usam a mesma tecla, o atalho do modo Navigate vence enquanto esse modo está aberto. Alt, Cmd/Super e pontuação com modificadores dependem das configurações do seu terminal e do tmux.

Se você tem atalhos personalizados antigos e quer os novos padrões, execute `herdr config reset-keys`. O Herdr faz backup do `config.toml`, remove `[keys]` e `[[keys.command]]` e usa os padrões v2 embutidos depois de reiniciar ou de `herdr server reload-config`.

## Saltos por índice

Atalhos indexados usam `1..9` nos campos normais de atalho:

```toml
[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"
```

O Herdr ainda lê a tabela legada `[keys.indexed]` por compatibilidade, mas configurações novas devem preferir os campos explícitos de ação.

## Atalhos de comandos personalizados

Comandos personalizados usam a mesma sintaxe de atalhos.

```toml
[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
```

`type = "popup"` abre um popup modal da sessão sem mudar o layout da aba. O popup recebe toda a entrada do terminal, inclusive Escape, até o comando terminar. `width` e `height` são opcionais. Omita os dois para o popup padrão com metade do tamanho, use números para células do terminal ou strings como `"80%"` para uma porcentagem da área do terminal. As dimensões incluem a borda do popup, e valores abaixo do mínimo do popup passam a valer esse mínimo. Comandos de popup não recebem `HERDR_PANE_ID`. Use `HERDR_ACTIVE_PANE_ID` para o painel lado a lado que fica por baixo.

No Unix e no macOS, um comando de popup também pode oferecer um terminal avulso sem adicionar uma divisão ou uma aba:

```toml
[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"
```

No Windows, use um comando de shell como `command = "powershell.exe -NoLogo"`. Saia do shell para fechar o popup e voltar à visualização dos terminais lado a lado.

`type = "pane"` abre um painel temporário com zoom e o fecha quando o comando termina.

`type = "shell"` roda desanexado em segundo plano.

`type = "plugin_action"` invoca o id de uma ação de plugin instalado. Use o id qualificado quando os ids de ação não forem únicos entre plugins:

```toml
[[keys.command]]
key = "prefix+l"
type = "plugin_action"
command = "example.layout.apply"
description = "apply layout"
```

`description` é opcional. Quando definido, aparece no painel de ajuda de atalhos (aberto com `prefix+?`) no lugar do rótulo padrão `'custom command'`.

Comandos personalizados recebem `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, `HERDR_ACTIVE_WORKSPACE_ID`, `HERDR_ACTIVE_TAB_ID`, `HERDR_ACTIVE_PANE_ID` e `HERDR_ACTIVE_PANE_CWD` quando esses valores estão disponíveis. Comandos de shell rodam a partir do diretório de trabalho do painel focado quando o Herdr consegue detectá-lo.

No Windows, as strings de comandos personalizados usam `cmd.exe /d /c`, então as variáveis de ambiente usam a sintaxe `%HERDR_BIN_PATH%`. Para rodar sintaxe do PowerShell, chame o PowerShell de forma explícita, por exemplo `powershell.exe -NoProfile -Command "..."`.

## Tema

Escolha um tema embutido:

```toml
[theme]
name = "catppuccin"
```

Procure `theme.name` na [Referência de configuração](/pt-br/docs/config-reference/) para ver todos os temas embutidos. Use `terminal` quando quiser que as cores da interface do Herdr sigam a paleta ANSI do terminal hospedeiro.

No Unix, o Herdr também relê as cores do terminal hospedeiro quando redesenha depois de um redimensionamento ou de um `SIGWINCH`. Se o seu alternador de temas muda as cores do terminal por OSC sem avisar da troca entre claro e escuro, envie `kill -WINCH <client-pid>` depois de aplicar a nova paleta. Envie o sinal para o cliente do Herdr anexado, não para o servidor. Os painéis existentes continuam rodando. Sessões diretas de `herdr terminal attach` deixam as consultas de paleta para a aplicação anexada.

Para o Herdr trocar o próprio tema da interface quando o terminal hospedeiro informar uma mudança de aparência entre claro e escuro, ative a troca automática de tema:

```toml
[theme]
name = "catppuccin"
auto_switch = true
light_name = "catppuccin-latte"
dark_name = "catppuccin"
```

`auto_switch` tem padrão `false`, então as configurações de tema existentes mantêm o comportamento manual. Se `light_name` ou `dark_name` for omitido, o Herdr usa a variante embutida correspondente ao `name` configurado quando ela existe, como `tokyo-night`/`tokyo-night-day` ou `gruvbox`/`gruvbox-light`. Escolher o tema manualmente em Settings desativa `auto_switch`.

Você pode substituir cores individuais:

```toml
[theme.custom]
sidebar_bg = "#181825"
active_row_bg = "#1e1e2e"
selection_bg = "#313244"
panel_bg = "reset"
accent = "#a6e3a1"
green = "#a6e3a1"
blue = "#89b4fa"
red = "#f38ba8"
yellow = "#f9e2af"
```

`sidebar_bg` é opcional e dá à barra lateral do desktop um fundo próprio. Quando omitido, a barra lateral mantém o fundo do terminal hospedeiro. `active_row_bg` muda o fundo da linha do Space ativo e do Agent focado sem afetar separadores nem trilhos da barra de rolagem. `selection_bg` muda o fundo da linha do cursor do modo Navigate na barra lateral.

Os valores de cor aceitam hex, nomes de cor, `rgb(r,g,b)` ou aliases de reset como `reset`, `default`, `none` e `transparent`.

Com `auto_switch` ativo, subtabelas opcionais de claro e escuro se sobrepõem às cores personalizadas compartilhadas:

```toml
[theme.custom]
accent = "#89b4fa"

[theme.custom.light]
panel_bg = "#eff1f5"
text = "#4c4f69"

[theme.custom.dark]
panel_bg = "#1e1e2e"
text = "#cdd6f4"
```

O Herdr aplica a paleta ativa nesta ordem: tema embutido, `[theme.custom]` e depois `[theme.custom.light]` ou `[theme.custom.dark]`. Sem as subtabelas de modo, a substituição compartilhada funciona como antes.

## Interface e barra lateral

A barra lateral é o painel de controle principal do Herdr. Procure `ui.` na [Referência de configuração](/pt-br/docs/config-reference/) para tamanho, modo recolhido, ordem do painel Agent, comportamento do mouse, bordas dos painéis e outras configurações de apresentação.

`ui.pane_borders` aceita `"auto"` (o padrão, com bordas só em painéis divididos), `"always"` (também emoldura um painel único) ou `"off"`. A moldura de um painel único exige `ui.pane_outer_borders = true`, porque todas as bordas dele são bordas externas. Os valores booleanos existentes continuam válidos: `true` equivale a `"auto"` e `false` equivale a `"off"`.

Defina `tab_bar_position = "bottom"` em `[ui]` para colocar a linha de abas do desktop abaixo dos painéis do terminal. As barras dos modos Prefix, Navigate, Copy e Resize substituem a linha de abas inferior enquanto estão ativas. O padrão é `"top"`.

Configure uma área de status ordenada, no estilo do tmux, na borda direita da linha de abas:

```toml
[ui]
tab_bar_right = [
  { type = "zoom" },
  { type = "hostname" },
  { type = "datetime", format = "%H:%M" },
  { type = "text", text = "prod" },
  { type = "command", command = "~/.config/herdr/status.sh", interval_seconds = 5, timeout_seconds = 2 },
]
tab_bar_right_separator = " · "
```

A área de status fica vazia por padrão. Adicione `zoom` para mostrar um marcador fixo `ZOOM` enquanto a aba ativa estiver com zoom. Os marcadores `Z` de cada aba continuam independentes. `hostname`, `datetime` e `command` são resolvidos no servidor do Herdr, então `herdr --remote` mostra os valores da máquina remota. Entradas de data e hora usam a formatação do `strftime`. O Herdr rejeita diretivas que exigem fuso UTC ou timestamp Unix, como `%z` e `%s`, porque o valor é a hora local do servidor.

Entradas de comando rodam na hora e depois a cada `interval_seconds`, sem bloquear a renderização nem sobrepor uma execução anterior. O intervalo pode ir de 1 a 31.536.000 segundos, e o timeout de 1 a 3.600 segundos. O Herdr usa a última linha da saída bem-sucedida e remove as sequências de controle de terminal iniciadas por ESC em vez de interpretar os estilos. Ele limpa a entrada depois de uma falha, de uma saída vazia ou de estourar `timeout_seconds`. O comando recebe o mesmo contexto dos atalhos de comandos personalizados: workspace, aba e painel ativos, socket, binário e diretório de trabalho. Os comandos funcionam no Linux, no macOS e no Windows, com `/bin/sh -lc` no Linux e no macOS e `cmd.exe /d /c` no Windows.

Os separadores aparecem só entre entradas visíveis. Defina `tab_bar_right_separator = ""` para juntar as entradas sem separador. Em uma linha de abas estreita, a área de status inteira cede espaço às abas e aos controles delas.

### Título da janela do terminal externo

O Herdr emula os terminais dos painéis, então um título `OSC 0`/`OSC 2` escrito dentro de um painel para no Herdr. O Herdr grava o próprio título no terminal onde ele roda, que é o título que gerenciadores de janelas e barras de abas do terminal leem:

```toml
[ui]
window_title = "{hostname}: {workspace}"
```

Os tokens são `{hostname}`, `{workspace}`, `{tab}`, `{pane}` (o nome manual do painel focado) e `{terminal_title}` (o título de terminal do próprio painel focado, sem os quadros do spinner). Escreva `{{` e `}}` para chaves literais. Um token sem valor fica vazio.

O título é renderizado no servidor do Herdr, então `{hostname}` nomeia a máquina onde os painéis rodam, inclusive quando você anexa com `herdr --remote` ou executa `herdr` por SSH. Defina `window_title = ""` para não mexer no título do terminal externo.

`client.window_title.set` substitui o título configurado até que `client.window_title.clear` o devolva.

O status dos agentes usa pontos coloridos compactos por padrão. Para distinguir os estados bloqueado, trabalhando, concluído, ocioso e desconhecido pela forma além da cor, escolha **distinct symbols** em Settings ou configure:

```toml
[ui]
status_indicators = "symbols"
```

Os símbolos são estáticos, então esta opção não ativa a animação do spinner.

### Layouts das linhas da barra lateral

A barra lateral expandida do desktop renderiza cada array interno de `rows` como uma linha. Estes são os layouts padrão completos:

```toml
[ui.sidebar.agents]
row_gap = 0
rows = [
  ["state_icon", "machine", "workspace", "tab"],
  ["agent"],
]

[ui.sidebar.spaces]
row_gap = 0
rows = [
  ["state_icon", "workspace"],
  ["branch", "git_status"],
]
```

As linhas de Agent aceitam estes tokens embutidos:

- `state_icon` mostra um ícone colorido do estado semântico do agente.
- `state_text` mostra `idle`, `working`, `blocked`, `done` ou `unknown`, incluindo o rótulo de exibição informado quando existe.
- `machine` mostra o rótulo da máquina quando o cliente tem várias máquinas. Com uma única máquina local, ele fica de fora.
- `workspace` mostra o nome do workspace.
- `tab` mostra o nome da aba quando disponível.
- `pane` mostra o nome do painel quando disponível.
- `agent` mostra o nome de exibição do agente detectado ou informado.
- `terminal_title` mostra o último título de terminal OSC 0/2 depois da normalização de segurança.
- `terminal_title_stripped` mostra o título do terminal sem um glifo inicial reconhecido de atividade ou spinner e sem o espaço em branco que vem depois dele.
- `$name` mostra o metadado personalizado do painel chamado `name`.

As linhas de Space aceitam estes tokens embutidos:

- `state_icon` mostra um ícone colorido do estado agregado dos agentes do space.
- `state_text` mostra o texto do estado agregado dos agentes.
- `workspace` mostra o nome do workspace.
- `branch` mostra a branch do Git quando disponível.
- `git_status` mostra quantos commits o Git está à frente e atrás, quando esses números não são zero.
- `$name` mostra o metadado personalizado do workspace chamado `name`.

Os tokens aparecem na ordem configurada. Normalmente o Herdr separa valores vizinhos com ` · ` e usa um único espaço depois de `state_icon`. Valores ausentes e os separadores deles somem. Uma linha some quando nenhum dos tokens dela tem valor. Linhas personalizadas existentes não mudam, então adicione `machine` de forma explícita se quiser a identidade da máquina em um layout personalizado com várias máquinas. Cada layout pode ter no máximo 16 linhas, com no máximo 16 tokens em cada linha.

Uma entrada de token também pode ser uma tabela inline de estilo:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", { token = "workspace", bold = false }, "tab"],
  [{ token = "$summary", fg = "#89b4fa", bold = true, dim = false }],
]
```

`fg` aceita estritamente `#RGB` ou `#RRGGBB`. `bold` e `dim` aceitam booleanos. Campos omitidos preservam o estilo contextual do token. Um `false` explícito remove aquele modificador. O estilo vale para uma ocorrência, então o mesmo token pode ter outra aparência em outra linha ou em outra substituição por agente. Uma substituição de cor de frente troca todas as cores semânticas de frente dentro daquela ocorrência. Por exemplo, as contagens de à frente e atrás de um `git_status` estilizado usam uma cor só, em vez do verde e do vermelho padrão. Os estilos de token nunca mudam separadores nem fundos de linha.

Tokens com valor de texto também aceitam até 16 `rules` em ordem. Cada regra contém exatamente uma condição (`equals`, `contains`, `starts_with`, `gt` ou `lt`) e substituições opcionais de `fg`, `bold` e `dim`:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "workspace", "tab"],
  [{ token = "machine", fg = "#fff", rules = [{ equals = "Local", fg = "#f55" }, { equals = "Fedora", ignore_case = true, fg = "#51a2da" }] }, "agent"],
  [{ token = "$load", fg = "#fff", rules = [{ gt = 80, fg = "#f55", bold = true }, { gt = 50, fg = "#fc0" }] }],
]
```

A primeira regra que casa vence. Os campos de estilo que ela especifica substituem os padrões da ocorrência, e os campos não especificados herdam esses padrões. Se nenhuma regra casar, os padrões continuam valendo. A comparação usa o valor completo do token, antes do corte para exibição. Defina `hide = true` em uma regra para remover o token que casou e o separador dele. Linhas sem nenhum token restante também somem. Por exemplo, `{ token = "machine", fg = "#61afef", rules = [{ equals = "Local", hide = true }] }` esconde o token da máquina quando o rótulo é exatamente `Local`. Isso compara o rótulo, não o tipo de conexão. Com `hide = false` ou sem `hide`, o token continua visível. Uma regra sem substituições também encerra a busca e mantém os padrões.

`equals`, `contains` e `starts_with` recebem strings e diferenciam maiúsculas de minúsculas. Adicione `ignore_case = true` para ignorar a caixa em caracteres ASCII. Caracteres fora do ASCII continuam diferenciando a caixa. Strings vazias seguem a comparação normal de strings: `equals` vazio casa só com um valor vazio, enquanto `contains` ou `starts_with` vazios casam com qualquer valor presente.

`gt` e `lt` recebem limites numéricos finitos e comparam com maior ou menor estrito, sem igualdade. Os valores precisam ser lidos por inteiro como números finitos. Formas decimais e com expoente funcionam, mas espaços em branco, unidades, `NaN` e infinito não casam. Regras numéricas não aceitam `ignore_case`. As comparações usam números de ponto flutuante, não aritmética exata de inteiros grandes.

As regras funcionam com os tokens embutidos de texto e com os tokens personalizados `$name` nas linhas de Agent, nas substituições de `rows_by_agent` e nas linhas de Space. Tokens personalizados comparam o valor informado. No exemplo acima, `$load` informando `"90"` seleciona vermelho e negrito, `"60"` seleciona amarelo e `"90%"` mantém o branco. Tokens não informados continuam sumindo. `state_icon` e o composto `git_status` aceitam só estilos fixos, não regras. O Herdr rejeita condições desconhecidas e regras malformadas ao carregar a configuração. Regex, busca aproximada e scripts não são suportados.

`row_gap` controla as linhas em branco do terminal entre as entradas, de forma independente para os painéis Agent e Space. O padrão é `0`, que junta as entradas. Defina `1` para voltar ao espaçamento anterior. Ele não adiciona espaço entre as linhas de conteúdo declaradas em `rows`. Filhos de worktree indentados e consecutivos continuam juntos como um grupo de Space.

Substitua o layout completo de Agent para um agente conhecido em `rows_by_agent`:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "state_text"],
  ["workspace", "tab"],
]

[ui.sidebar.agents.rows_by_agent]
claude = [
  ["state_icon", "agent", "state_text"],
  ["terminal_title_stripped"],
  ["workspace", "tab"],
]
```

Uma substituição troca `rows` inteiro, não estende. As chaves de substituição são IDs canônicos de agente, com diferença entre maiúsculas e minúsculas, como `claude`, `codex` e `pi`. Aliases de detecção como `claude-code` não são aceitos. Agentes sem substituição, inclusive agentes personalizados informados, usam `rows`.

Tokens personalizados `$name` são valores dinâmicos, não texto literal. Adicione o token a um layout e depois informe o valor dele a partir de um script ou plugin:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "$model"],
  ["$summary"],
  ["workspace", "tab"],
]
```

```bash
herdr pane report-metadata <pane_id> \
  --source my-agent-hook \
  --token model=opus \
  --token summary="reviewing authentication"
```

Use `herdr workspace report-metadata` da mesma forma para tokens personalizados de Space. Tokens personalizados não informados somem.

Quem informa metadados fornece só os valores. O estilo fica na configuração local da barra lateral. Veja [Referência da CLI: informar metadados](/pt-br/docs/cli-reference/#painéis) para limites, limpeza, sequência e expiração.

As configurações de linhas da barra lateral afetam só a barra lateral expandida do desktop. As visualizações recolhida e mobile mantêm os layouts compactos.

## Notificações

O Herdr pode avisar você quando um agente em segundo plano termina ou precisa de uma resposta:

```toml
[ui.toast]
delivery = "herdr"
delay_seconds = 1

[ui.toast.herdr]
position = "bottom-right"
```

Escolha `herdr` para um toast dentro do app, `terminal` para uma notificação do terminal externo que também funciona por SSH, `system` para o serviço de notificações do sistema operacional local ou `off` para desativar os popups. O Herdr não mostra popups da aba ativa. Procure `ui.toast` na [Referência de configuração](/pt-br/docs/config-reference/) para posições, comportamento do atraso e configurações de retorno da área de transferência.

No macOS, `system` tenta primeiro o `terminal-notifier` e recorre ao `/usr/bin/osascript` quando ele não está disponível ou falha. Com esse recurso, a notificação aparece como Script Editor na Central de Notificações e não consegue ativar o terminal hospedeiro. Instale o `terminal-notifier` com `brew install terminal-notifier`. Em um terminal suportado e detectado, ele consegue ativar o app do terminal quando você clica na notificação. Outra opção é escolher `terminal` para deixar a notificação com um terminal externo suportado.

## Som

As notificações sonoras tocam pelo cliente local do Herdr. Sons personalizados precisam ser arquivos mp3. O Herdr resolve caminhos relativos a partir do diretório do arquivo de configuração.

```toml
[ui.sound]
path = "sounds/notification.mp3"
done_path = "sounds/done.mp3"
request_path = "sounds/request.mp3"
```

`path` define um som para todas as notificações sonoras. `done_path` e `request_path` substituem só os sons de concluído e de pedido de resposta.

As substituições de som por agente aceitam `default`, `on` ou `off`. Use rótulos de agentes detectados, como `claude`, `codex`, `devin` ou `droid`, como chaves. O Droid fica sem som por padrão.

```toml
[ui.sound.agents]
droid = "off"
claude = "on"
```

## Gráficos do Kitty

Aplicações e plugins se integram pelo protocolo padrão de gráficos do Kitty, emitido na saída de terminal do painel. O Herdr renderiza essas imagens por padrão em terminais externos compatíveis. A API de sobreposição de painéis do socket externo foi removida, e não há API de imagens no socket para substituí-la.

Popups, menus e notificações escondem temporariamente só as imagens que eles cobrem. Imagens descobertas continuam visíveis, e as escondidas voltam quando deixam de estar cobertas. As imagens não escurecem junto com o fundo dos diálogos.

O Herdr escolhe sozinho os transportes por arquivo elegíveis, sem mudanças na aplicação nem variáveis de ambiente. Em clientes Ghostty locais no Unix, ele pode enviar os dados das imagens por arquivos temporários em vez de codificá-los na saída do terminal. Antes, um pequeno teste de leitura de arquivo confere o suporte. Outros terminais, clientes iniciados por SSH e multiplexadores aninhados mantêm a saída inline nesse último trecho.

Em clientes locais elegíveis, as imagens RGBA nativas vão do servidor ao cliente como caminhos de snapshots do Herdr, não como bytes de pixel. Clientes sem suporte e transferências que falham voltam para a entrega inline. O Herdr nunca repassa caminhos do servidor remoto ao terminal local. O posicionamento, o recorte e a visibilidade das imagens ficam sob controle do Herdr.

No Linux, uploads RGBA de arquivo inteiro e sem compressão podem usar snapshots copy-on-write antes de o Herdr ler os pixels. Isso exige que o sistema de arquivos permita clonar para o armazenamento privado do Herdr em `/var/tmp`. Sistemas de arquivos sem suporte, uploads por arquivo temporário, memória compartilhada e outros formatos usam o carregador normal. Os snapshots têm limite de 16 MiB cada e 64 MiB no total. Animações e clientes sem suporte leem os pixels quando precisam. O Herdr nunca depende de um caminho mutável do produtor depois de aceitar uma imagem.

Uploads PNG mantêm a decodificação e a validação completas. O Herdr não deixa para o terminal externo a validação de imagens corrompidas.

Para desativar a renderização de gráficos do Kitty:

```toml
[terminal]
kitty_graphics = false
```

A configuração legada `experimental.kitty_graphics` continua aceita nas configurações existentes. `terminal.kitty_graphics` tem precedência quando as duas estão definidas.

Mudar essa configuração exige reiniciar o servidor do Herdr afetado ou reanexar o cliente. Em sessões remotas, a configuração do servidor controla a leitura dos gráficos do Kitty, e a configuração do cliente local controla a saída para o terminal externo.

## Restauração da sessão dos agentes

Por padrão, o Herdr retoma as conversas de agentes suportados depois de um reinício do servidor:

```toml
[session]
resume_agents_on_restore = true
startup_per_agent_delay_ms = 100
```

As restaurações automáticas iniciam um agente por vez, com 100 milissegundos de intervalo por padrão, para reduzir a disputa na inicialização. O primeiro agente elegível começa na hora. Defina `startup_per_agent_delay_ms = 0` para tirar o intervalo. Execuções manuais e anexações explícitas de terminal não mudam. Reinicie o servidor do Herdr para aplicar as mudanças.

Só painéis com uma referência válida de sessão nativa, vinda de uma integração oficial, podem ser retomados. Os outros painéis voltam como shells normais. Veja [Estado e restauração da sessão](/pt-br/docs/session-state/) para os agentes suportados e o comportamento da persistência.

## Rastreamento do cursor do IME

No macOS, TUIs de agentes de IA que escondem o cursor de hardware podem impedir que as janelas de candidatos do método de entrada nativo acompanhem o painel focado. Mostre uma âncora de cursor nesses painéis com:

```toml
[experimental]
reveal_hidden_cursor_for_cjk_ime = true
cjk_ime_agents = ["claude", "pi", "codex"]
```

Restringir `cjk_ime_agents` evita mostrar um cursor de hardware extra em aplicações sem relação com os agentes. Procure essas chaves na [Referência de configuração](/pt-br/docs/config-reference/) para ver os nomes de agentes e os formatos de cursor aceitos.

## Troca da fonte de entrada no prefixo

No macOS e no Windows, o Herdr pode trocar temporariamente para uma fonte de entrada compatível com ASCII enquanto os comandos de prefixo e os modos abertos pelo prefixo estão ativos:

```toml
[experimental]
switch_ascii_input_source_in_prefix = true
```

No macOS, isso troca para o layout de teclado atual compatível com ASCII. No Windows, troca o IME para a entrada em inglês (ASCII). O Herdr restaura a fonte de entrada anterior quando volta para a entrada do terminal ou entra em um campo de texto. Esta configuração não tem efeito em outras plataformas.

:::caution[No Windows, só o IME coreano tem suporte]
No Windows, o suporte hoje se limita ao IME coreano. Com um IME de qualquer outro idioma, esta configuração não muda a fonte de entrada.
:::

## Variáveis de ambiente

| Variável | Finalidade |
| --- | --- |
| `HERDR_CONFIG_PATH` | Substitui o caminho do arquivo de configuração. |
| `HERDR_SESSION` | Seleciona uma sessão nomeada para os comandos da CLI. |
| `HERDR_SOCKET_PATH` | Substituição de baixo nível do caminho do socket. |
| `HERDR_PROCESS_DETECTION` | Estratégia de detecção de processos no Linux: `native` (padrão) ou `child-groups`, que precisa ser ativada. |
| `HERDR_LOG` | Define o filtro de logs, por exemplo `HERDR_LOG=herdr=debug`. |
| `HERDR_DISABLE_SOUND` | Desativa a reprodução de som mesmo com `[ui.sound] enabled = true`. |

## Logs

Os logs ajudam a diagnosticar avisos de inicialização, o estado das integrações ou o comportamento da API do socket.

Arquivos de log comuns:

```text
~/.config/herdr/herdr.log
~/.config/herdr/herdr-client.log
~/.config/herdr/herdr-server.log
```

O Herdr rotaciona os logs automaticamente. Ao relatar problemas, inclua o log atual e os arquivos rotacionados ao lado dele.
